# 个人学习回顾

这份回顾关注的是用户主动投入在个人提升上的时间，而不是工作中所有可能带来认知收益的活动。数据来自日记中的学习记录和同周期微信读书数据。日常工作天然包含学习成分；如果把这些活动全部纳入，会高估个人学习投入，也会掩盖真正留给自我提升的时间。

## 日期范围

1. 使用用户指定的日期范围。
2. 用户未指定时，通过 shell `date` 获取当日，默认回顾“当日-6d～当日”，即包含当日在内的最近 7 个自然日。
3. 从 `journals` 文件夹读取范围内的日记。
4. 微信读书接口按自然周、自然月等固定周期返回数据。回顾范围与固定周期不一致时，将范围拆成相交的自然周查询，再按日期分桶截取目标日期。

## 微信读书数据

调用 `weread-skills` 获取同一日期范围内的微信读书数据。调用前先读取该 skill 的 `SKILL.md` 和 `readdata.md`，遵守其中的鉴权、版本、字段单位和升级要求。

### 查询与统计口径

1. 找出回顾范围覆盖的所有自然周，对每周调用 `/readdata/detail`，传入 `mode=weekly`、该周内的 `baseTime` 和当前 `skill_version`。
2. 若回顾范围完整覆盖某个自然周，该周总时长使用 `totalReadTime`；若只覆盖自然周的一部分，使用 `readTimes` 中落在范围内的日分桶求和，并说明采用了按日分桶口径。
3. 如果边界周缺少完整的日分桶，不能把整周 `totalReadTime` 当作目标范围的时长。将微信读书时长标记为“无法精确统计”，不要并入本期实际投入总计。
4. `totalReadTime`、`readTimes` 和 `readLongest[].readTime` 的单位均为秒，展示时统一转换为分钟或“XhXmin”。
5. 统计有效阅读天数时，以目标范围内单日阅读满 1 分钟为有效；不要直接相加相交自然周的 `readDays`，因为其中可能包含范围外日期。
6. 汇总相交自然周的 `readLongest`，展示主要阅读书目、有声内容、作者、阅读/收听时长及标签。只有回顾范围完整覆盖对应自然周时，单本时长才能视为目标周期精确值；边界周书目需标注为“相交自然周主要书目”，不要声称单本时长完全发生在目标周期内。
7. 可展示 `readStat` 中的读过、读完、笔记等信息，但它同样属于接口请求的自然周期。范围未与自然周期对齐时，需标明其覆盖口径，不能当作目标范围的精确增量。
8. 接口失败、缺少 API Key 或返回数据不足时，继续完成日记侧回顾。在结果中写明“微信读书数据未获取”，不要把数据缺失解释为阅读投入为 0。

### 与日记学习时间合并

- 微信读书的精确周期时长属于已经实际发生的个人阅读，计入本期个人学习总投入。
- 如果日记也记录了同一次微信读书，优先使用微信读书数据，并从日记侧学习投入中排除这笔重复时长。
- 分别展示“日记可确认学习投入”“微信读书阅读投入”和“本期个人学习总投入”，使合并口径可核查。
- 微信读书中读到的书目可以进入“学习内容”，但不要仅根据书名虚构学习结论。只有存在日记、划线、想法或其他证据时，才总结具体认知收获。

## 纳入标准

先从日记中找出带 `#学习` 标签、学习语义明显，或投入记录能够证明已经发生的候选事项。标签只是候选信号，不代表一定纳入。

一项活动只有在满足以下条件时才纳入：

1. **首要目的为个人提升**：为了扩展知识、训练技能、改进思维方式或建立个人方法体系，而不是为了完成当前岗位职责或项目交付。
2. **已经实际发生**：任务标记为完成，或投入记录、时间戳明确说明已经学习或练习。仅列入计划但未完成的事项不纳入。
3. **存在具体学习行为**：如阅读书籍或文章、参加个人课程、观看教程、刻意练习、个人研究、以学习为主要目的的实验、写学习笔记、复习与反思。

可以用这个反事实问题辅助判断：

> 如果没有当前这项工作任务、项目交付或组织要求，用户是否仍可能为了提升自己而主动做这件事？

- 答案明显为“是”：通常纳入。
- 答案明显为“否”：属于工作投入，排除。
- 无法判断：默认排除，避免把工作时间误算成个人学习；可在“边界说明”中简短列出。

## 排除标准

以下活动即使包含学习、复盘、知识传播或能力运用，也默认不计入个人学习投入：

- 日常会议、业务研讨会、项目沟通会、周会、SIG 会议和跨团队对齐。
- 为完成岗位职责而进行的需求研究、方案讨论、故障处理、技术调研或项目探索。
- 周报、双周报、汇报材料、设计文档、项目文档、流程图等工作交付。
- 内部宣讲、工作培训筹备、培训大纲登记、分享排期及组织要求的知识沉淀。
- 精进互通“登记”动作本身。登记中提到的底层个人学习活动若有独立证据，可以单独纳入。
- 仅因名称中出现“AI”“知识”“研究”“复盘”“文档”“Skill”等词而看起来像学习的工作任务。
- 个人提升意图不清楚、同时又直接服务于当前项目交付的混合事项。

判断活动而不是判断主题。同一个主题可能有不同归属：

- 下班后主动阅读 AI Coding 原理并做个人练习：纳入。
- 为提交 AI Coding 周报而整理项目数据：排除。
- 主动研究个人 Skill 管理方法并做实验：纳入。
- 按团队要求编写 Skill 相关培训材料：排除。
- 阅读一本书并整理个人笔记：纳入。
- 参加知识库项目例会并输出流程图：排除。

## 实际时间统计

回顾的核心指标是**实际投入**，不要用预估时间替代实际投入。

每日计划中的符号含义：

- 🍅：预估 25min。
- 🍉：预估 15min。
- 🥔：实际投入 25min。
- 🍠：实际投入 15min。

按以下优先级确定实际时间：

1. 日记明确记录的实际时长或起止时间。
2. 实际投入符号 🥔、🍠。
3. 连续投入记录能够可靠推算的时间段。
4. 如果只有 🍅、🍉 等预估符号，没有实际投入证据，则记录为“实际时长未记录”，不计入实际投入合计。

不要重复计算同一活动的任务标记、时间戳和文字记录。时间证据冲突时，优先采用明确写出的实际时长，并在统计口径中说明。

## 回顾流程

1. 读取日期范围内的日记，收集可能属于个人提升的候选活动。
2. 逐项应用纳入与排除标准，尤其区分“个人主动学习”和“工作中顺带学习”。
3. 调用 `weread-skills` 获取同周期阅读统计，计算目标日期范围内的阅读时长、有效阅读天数和主要书目。
4. 仅对纳入事项做结构化总结，并按主题归类。
5. 统计每项日记学习投入、微信读书阅读投入和本期个人学习总投入。可以把预估时间作为辅助信息，但不要让计划量成为核心结论。
6. 检查日记与微信读书是否记录了同一次阅读，合并时去重。
7. 简要说明：
   - 个人学习时间主要投向了什么；
   - 微信读书的阅读连续性、主要书目和阅读/收听结构；
   - 学习是否形成笔记、练习、实验或其他可复用产物；
   - 哪些个人学习计划反复出现但没有实际投入。
8. 如有容易误判的工作相关事项，在“边界说明”中列出 1～3 个代表性排除案例，解释为什么没有纳入。不要罗列全部工作任务。
9. 将结果追加到日期结束日对应日记的末尾。不要修改、重写或删除原有内容，只做追加。

## 输出结构

使用以下结构，省略没有内容的部分：

```markdown
## 个人学习回顾（YYYY-MM-DD～YYYY-MM-DD）

> [!summary] 本期概览
> 完成了几项个人学习，日记与微信读书合计实际投入多少，主要学习和阅读方向是什么。

### 学习内容

按主题结构化总结具体学习活动及形成的产物。

### 微信读书

> [!info] 阅读口径
> 说明查询的自然周期、目标日期截取方式，以及书目数据是否包含边界周。

- 阅读时长：Xmin（XhXmin）
- 有效阅读：X天
- 主要书目：
  - 《书名》— 作者，阅读 Xmin
- 阅读产出：读完、笔记或划线情况（仅在数据口径支持时展示）

### 实际投入

| 日期 | 学习事项 | 实际投入 | 时间依据 |
|---|---|---:|---|

**日记可确认学习投入：Xmin（XhXmin）**  
**微信读书阅读投入：Xmin（XhXmin）**  
**本期个人学习总投入：Xmin（XhXmin）**

### 关键观察

- 个人学习投入的分布与连续性。
- 微信读书阅读是否稳定，主要阅读时间投向了哪些书目。
- 学习是否从输入转化为练习、笔记或方法。
- 未发生实际投入的个人学习计划。

### 边界说明

- 哪些容易误判的工作活动被排除，以及排除原因。

### 下一步建议

给出 1～3 条与个人提升直接相关、可以执行的建议。
```

如果日记中没有符合条件的个人学习，但微信读书存在精确的周期内阅读时长，仍将这部分阅读作为个人学习投入，并明确说明日记侧未发现其他可确认学习。

如果日记和微信读书都没有符合条件的个人学习，不要用工作活动填充结果。应明确写“本期未发现可确认的个人学习投入”，实际投入记为 0，并可指出有计划但未落实的个人学习事项。

如果微信读书数据获取失败，不能据此判断阅读为 0；只汇总日记侧可确认投入，并在概览和“微信读书”部分标明数据缺失。

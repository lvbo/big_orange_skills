# 工作周报

## 范围约定

- 默认回顾上一完整 ISO 周；用户明确指定“本周”或某周时遵从用户。ISO 周为周一至周日，文件标识使用 `%G-W%V`，跨年时不要用 `%Y`。
- 日记位于 `journals/YYYY-MM-DD.md`。
- 晨记位于 `journals-morning/`，文件名前缀为书写日的 `YYYYMMDD`。D+1 的晨记通常回顾 D，应按被回顾日期归属。日记“晨间日记”章节中指向文件日期 D 的链接通常回顾 D-1；只有链接目标或正文明确说明归属 D 时才作为例外。
- 只提炼与工作有关且有来源支持的内容。个人生活、纯阅读统计和无关事项不进入工作周报。

## 工作流程

1. 取得系统日期和时区，计算目标 ISO 周的周一、周日及 `%G-W%V`，目标文件为 `journals-week/%G-W%V.md`。
2. 读取目标周内存在的日记及归属于各日的次日晨记。记录素材覆盖日期和缺失日期。
3. 提取并按主题合并工作事实，重点关注：
   - 重点项目与交付进展；
   - 团队管理、规划与团队建设；
   - 异常处理、风险与阻塞；
   - 人员沟通、跨团队协作；
   - 学习、文档和可复用产出。
   合并同一事项的多日记录，保留结果、影响和后续动作；不要用泛泛表述补齐不存在的成果。
4. 将事实与分析分开：正文描述可核验进展，“本周思考”可给出有根据的推断，“值得深思”提出 1–3 个具体问题。无法从素材确认的状态标为“待确认”。
5. 写入目标周文件中的工作周报稳定区块。将模板中的 `%G-W%V` 替换为具体 ISO 周，例如 `2026-W01`，不要原样写入占位符。文件不存在则创建；区块已存在则只替换区块。没有标记时，只有能唯一识别一个旧版工作周报章节且边界不跨入个人周回顾或其他受管区块时，才原位升级；多个候选或边界不明时停止并报告。不得覆盖同文件中的“个人周回顾”或其他内容。

```markdown
<!-- writing-weekly-report:start %G-W%V -->
## 工作周报

### 本周重点进展
- **事项：** 进展、结果与影响

### 团队与协作
- ...

### 异常、风险与待协调
- ...

### 文档、学习与沉淀
- ...

### 下周重点
- [ ] ...

### 本周思考
...

### 值得深思
1. ...

**素材覆盖：** ...
<!-- writing-weekly-report:end %G-W%V -->
```

6. 写入后重新读取文件，确认：目标 ISO 周正确；工作周报起止标记各恰好一个；同文件的 `week-review` 区块及区块外原文未被改动。验证失败时报告失败，不声称完成。

## 空素材与异常处理

- 七天均无可用日记时，不生成臆测周报、不写文件；列出检查范围并停止。
- 部分日期或晨记缺失时可继续，但在“素材覆盖”中明确说明。
- 多个目标文件或晨记候选无法可靠消歧时，停止写入并向用户说明冲突。

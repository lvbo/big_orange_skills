# pages-ai 笔记去 AI 味

根据用户给出的文件名定位一篇 `pages-ai/` 笔记，使用 `humanizer-zh` 改写正文，并把结果另存到原目录。原文件是用户内容，始终保留不动。

## 工作边界

- 只在当前 Vault 的 `pages-ai/` 及其子目录搜索 Markdown 文件。
- 不读取或改写 `raw/`、`wiki/`、`outputs/`、`journals*/` 中的同名文件。
- 不覆盖、移动或重命名原文件。
- 输出文件名为 `<原文件名（不含末尾 .md）>-去掉AI味.md`。例如 `复盘.md` 输出为 `复盘-去掉AI味.md`。
- 除非用户明确指定，否则不要把已经以 `-去掉AI味` 结尾的文件当作源文件。

## 工作流

### 1. 定位 Vault 与候选文件

确认当前目录或已知工作区是包含 `pages-ai/` 的 Vault 根目录。从本 Skill 目录运行：

```bash
python3 scripts/find_pages_ai_note.py --vault "/absolute/path/to/vault" --name "用户输入的文件名" --json
```

脚本会先找同名文件，再给出按文件名相似度排序的候选。不要只凭标题猜路径。

- 只有一个 `exact` 候选：直接使用。
- 多个 `exact` 候选：列出相对路径，让用户选择；本轮不写文件。
- 没有同名但只有一个可信的 `similar` 候选：说明采用了哪个相似文件，再继续。可信候选通常应排第一，且名称差异只是扩展名、空格、标点、大小写或少量字符。
- 有多个难以区分的相似候选：列出最相关的 2–5 个相对路径，让用户选择；本轮不写文件。
- 没有候选：报告未找到，不扩大到 `pages-ai/` 以外。

用户选择后，从定位步骤继续，不再重复询问已确定的信息。

### 2. 读取原文与 humanizer-zh

完整读取源文件和可用的 `humanizer-zh` skill 指引，再按其规则改写。这里的目标是让文字更像用户本人写的，同时维持笔记原来的用途和语气，不是把内容改成统一的散文风格。

改写时遵守以下保护规则：

- 保留 YAML frontmatter 的字段、值和顺序；除非用户明确要求，不改 frontmatter。
- 保留 Obsidian WikiLink、嵌入、标签、脚注、块引用 ID、callout 类型和 Markdown 链接目标。
- 保留代码块、行内代码、命令、路径、公式、表格数据、日期、数字、专有名词和引用内容的事实含义。
- 标题和列表可以在不破坏结构与语义的前提下调整措辞，但不要机械地把所有列表改成段落。
- 不补造事实、出处、个人经历、情绪或观点。原文没有证据时，宁可删去空泛主张，也不要用虚构细节替代。
- 区分作者正文与引用、代码、模板占位符；不要把被引用的原话“人性化”。

### 3. 生成新文件

在源文件所在目录写入 `<源文件 stem>-去掉AI味.md`，使用 UTF-8，并保留合理的末尾换行。

如果目标文件已经存在，不要静默覆盖。报告目标路径并询问用户是覆盖、换名还是取消；得到选择前不写入。

写入时只创建目标文件，不修改原文件或其他笔记。

### 4. 写后验证

重新读取源文件和目标文件，至少确认：

1. 原文件内容和路径未改变。
2. 目标文件与源文件位于同一目录，文件名正确。
3. frontmatter 与受保护的 WikiLink、代码块、链接目标、数字等仍然存在。
4. 目标正文已实际改写，不是原文的逐字副本，也没有附加聊天式说明、评分表或“所做更改”清单到笔记正文。
5. 没有生成额外文件。

验证失败时修正可安全修正的问题；无法安全修正就保留原文件并明确报告，不声称完成。

## 完成汇报

成功时只需简要说明：

```markdown
已生成：pages-ai/.../原文件名-去掉AI味.md
原文件未修改。
```

若因多候选或目标已存在而暂停，列出可选的 Vault 相对路径，并问一个直接问题。不要提前创建任何版本。

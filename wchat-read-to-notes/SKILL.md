# 微信读书笔记整理

调用 `weread-skills` 获取可验证的个人笔记数据，先保真导出，再形成结构化二次整理版。不得用公开热门划线替代用户自己的笔记，也不得为了下载图片自动操作 macOS 微信读书 GUI。

## 前置读取与能力边界

执行前完整读取：

1. `weread-skills` 目录中的 `SKILL.md`：鉴权、版本上报、接口调用和升级规则。
2. 同目录的 `search.md`：书名搜索、`scope=10`、bookId 获取与分页。
3. 同目录的 `notes.md`：个人划线和想法接口、字段含义与分页。
4. 同目录的 `book.md`：调用 `/book/info` 核对书名、作者和书籍信息。

从可用 Skill 列表定位 `weread-skills` 的实际路径；开发仓库中通常位于 `../../weread-skills/skills/weread/`。接口细节以这些文件的当前版本为准，不把版本号或未经确认的参数复制固化在本 Skill 中。

可导出的内容是：

- `/book/bookmarklist` 返回的个人划线；
- `/review/list/mine` 返回的个人想法、章节点评和整本书评；
- 书签目前只有数量，没有可导出正文。不要把划线称为书签。

## 书籍定位与失败处理

1. 用户给出 `bookId` 时直接使用，并查询书籍信息核对标题和作者。
2. 只有书名时，用 `/store/search` 且显式传 `scope=10` 获取候选。
3. 仅当结果能由书名和作者唯一确认时自动选择。存在同名书、不同版本或多个近似结果时，列出书名、作者等可用信息，请用户选择；不要猜 bookId。
4. 在后续对话中保持已确认的 `bookId`，避免重复消歧。
5. 若缺少 `WEREAD_API_KEY`、鉴权失败、接口报错或回包要求升级，按 `weread-skills` 的规则停止并提示。不要用空数据覆盖已有笔记，也不要生成看似成功的半成品。

## 完整拉取与归一化

1. 同时获取 `/book/bookmarklist` 和 `/review/list/mine`，因为“所有个人笔记”包括划线与想法/点评。
2. `/review/list/mine` 按文档使用 `synckey` 和 `hasMore` 拉取全部页；不要只保存第一页。搜索或其他接口需要翻页时，也只使用对应文档规定的游标。
3. 用章节信息将内容归入章节。无法定位章节的整本书评或普通想法放入“全书想法与点评”。
4. 按稳定 ID 去重：划线使用 `bookmarkId`，想法/点评使用 `reviewId`。缺少 ID 时使用 `bookId + 类型 + 章节 + range + createTime` 作为备用键，并在验证报告中注明。
5. 能关联原文的想法，优先用 `abstract`/`range` 与划线配对；不能可靠配对时分开展示，不凭文本相似度强行归并。

## 输出路径与文件身份

使用接口返回的规范书名，清理文件名中的 `/ : * ? " < > |`：

- 保真导出：`pages-ai/{书名}-读书笔记.md`
- 二次整理：`pages-ai/{书名}-读书笔记-二次整理版.md`

两个文件都用 `book_id` 作为稳定身份。若标题变化或已有文件名不同，先在 `pages-ai/` 中查找相同 `book_id` 的文件并原位更新，不创建重复副本。

### Frontmatter

```yaml
---
title: "书名读书笔记"
book_title: "接口返回的书名"
author: "接口返回的作者"
book_id: "微信读书 bookId"
source: "微信读书"
note_type: "verbatim|synthesis"
created: "YYYY-MM-DD"
updated: "YYYY-MM-DD"
tags:
  - 读书笔记
  - 微信读书
---
```

首次创建后保留 `created`，同步时只更新 `updated`。未知字段留空，不猜测。

## 保真导出模板

```markdown
# 《书名》读书笔记

> [!info] 同步说明
> 本页包含微信读书可导出的个人划线、想法和点评；书签仅有数量时只记录数量。

## 书籍信息

- 作者：
- 微信读书 ID：
- 可导出划线：N
- 可导出想法/点评：N
- 书签数量：N（仅当可靠获取）

<!-- weread-sync:start -->
## 第一章 章节名

### 划线

> 划线原文

- 来源：`underline:{bookmarkId}`
- 位置：`chapterUid=...; range=...`

#### 我的想法

想法原文

- 来源：`review:{reviewId}`

## 全书想法与点评

无法关联到具体划线的内容。
<!-- weread-sync:end -->

## 我的补充

此区块供用户手工维护，同步时保留。
```

保留划线与想法的原始措辞，不把模型概括混进保真区。每条内容保留稳定来源标识；时间如需展示，按 `weread-skills` 规则转换，不直接显示 Unix 时间戳。

## 二次整理模板

```markdown
# 《书名》读书笔记·二次整理

> [!note] 整理范围
> 本文只基于 [[书名-读书笔记]] 中的个人划线和想法整理。

<!-- weread-synthesis:start -->
## 一句话总结

## 核心观点

### 观点一

- 解释：
- 原文依据：`underline:{bookmarkId}`
- 我的想法：`review:{reviewId}`（如有）

## 概念与方法

## 可行动清单

- [ ] 可从笔记证据合理推出的行动；无法推出时不硬凑。

## 值得复习的问题

- 问题
  - 参考答案：
  - 依据：`underline:{bookmarkId}` / `review:{reviewId}`

## 金句与关键原文

只选择少量真正关键且来自个人划线的原文，并保留来源 ID。

## 我的疑问与待验证

区分作者观点、我的想法和模型提出的待验证问题。
<!-- weread-synthesis:end -->

## 我的补充

此区块供用户手工维护，重整时保留。
```

整理目标是提升复习价值，不是机械保留所有接口字段。删除无助于理解的技术元数据，但不得丢失支撑结论所需的来源 ID，也不得把模型生成的观点冒充用户想法或书中原文。

## 图片处理

只有存在可执行的数据来源时才处理图片：

- API 明确返回的封面或图片 URL；
- Vault 中已存在、且能明确对应本书的图片；
- 用户直接提供的本地图片或 URL。

处理步骤：下载或复制到 `assets/weread/{bookId}/`，使用不冲突的稳定文件名，在 Markdown 中用相对嵌入链接引用，并验证文件存在、大小非零、格式可读取。重复运行复用同一文件，不重复下载或创建副本。

如果接口不提供正文插图 URL、原笔记只含无法访问的占位符，或没有合法可用的数据来源：

- 不启动、不脚本控制 macOS 微信读书或其他 GUI；
- 不截图模拟下载，不猜图片内容；
- 保留文字笔记，在“同步说明”中写明“正文插图因无可执行来源未导入”；
- 若图片对任务关键，请用户提供文件或可访问 URL 后再继续。

## 幂等更新

- 用 `book_id` 定位现有两份文件，用稳定内容 ID 判重。
- 自动生成内容只写入 `weread-sync` 或 `weread-synthesis` 标记之间；重跑时替换对应区块，不在末尾重复追加。
- 只有开始或结束单边标记时停止并报告，不自行猜测覆盖范围。旧版文件没有标记时，只有 `book_id` 已匹配，或书名与作者都能唯一对应当前书籍时，才保留原文并在末尾追加首个受管区块；无法唯一确认时先请用户消歧，不覆盖旧文件。
- 保留 frontmatter 中未知的用户字段，以及标记区块之外的手工内容。
- API 拉取失败或数据明显不完整时不更新生成区块。
- 同一批数据重复运行后，除 `updated` 在内容确有变化时更新外，文件应保持不变。

## 写后验证与汇报

写入后复读两份文件并验证：

1. YAML 可解析，`book_id`、标题、作者和 `note_type` 正确。
2. 划线和想法数量与去重后的 API 数据一致；所有分页已结束。
3. 每个引用的 `underline:`/`review:` ID 都存在于保真导出中，二次整理没有无来源的“原文”。
4. 章节分组合理，原文、用户想法和模型整理清楚区分。
5. 标记区块各只有一对，用户手工内容未丢失。
6. 所有嵌入图片可读取；降级时已记录原因且没有启动 GUI。

最后汇报：确认的书名和 bookId、拉取页数、划线/想法/书签数量、创建或更新的文件、图片成功数或降级原因，以及任何未解决问题。

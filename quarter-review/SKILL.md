# 季度回顾

把三个月的记录压缩成一份 3～5 分钟能读完的个人季度复盘。季度回顾关注跨月变化、真正结果和下一季度取舍，不逐月复述，也不堆叠日记细节。

## 日期与文件范围

1. 通过 shell 的 `date` 获取当前日期，不凭对话时间猜测。
2. 按自然季度确定范围：Q1 为 1～3 月，Q2 为 4～6 月，Q3 为 7～9 月，Q4 为 10～12 月。
3. 用户指定季度时按其表述处理；“本季度”指当前自然季度，“上季度”指前一个自然季度。只说 `Qn` 时优先使用当前年份；若该季度尚未开始且语义明显指过去，使用上一年并在写入前说明判断。
4. 用户未指定季度时，使用上一个已经结束的自然季度。即使今天是季度末，也不要把尚未结束的本季度当作默认范围。
5. 在 vault 根目录先枚举以下素材并核对日期，再读取内容；`raw/` 始终只读且不属于本流程：
   - `journals-month/YYYY-MM.md`：目标季度三个月的月回顾，是主要证据源。
   - `journals-week/YYYY-Www.md`：与目标季度相交的周回顾，用于补足月回顾缺口和识别跨月模式。
   - `journals/YYYY-MM-DD.md`、`journals-morning/`：仅在月回顾缺失、证据冲突、关键结论需要核验，或用户明确要求重算时下钻读取。晨记按正文实际回顾日期归属，通常是 D+1 回顾 D。
   - `journals-month/<上一季度 YYYY-Qn>.md`：仅用于承接上季度目标或做可靠对比；不存在时不要扩大扫描范围补算。
6. 跨季度周回顾只采用能明确归属于目标季度的事实；无法拆分的周级数字只作背景。

## 证据与压缩口径

- 优先使用月回顾已经核验的事实与口径。三个月口径一致时可以汇总；口径不同、月份缺失或存在重复时写 `—` 或定性结论，不制造季度精确值。
- 同一事项跨月持续推进时合并成一条“行动—结果—边界”，不要按月份重复列出。计划、推进中、阶段完成和最终完成要明确区分。
- 关键结果只保留 3～5 项；每项说明结果或影响，并附 1～3 个最有代表性的日期、月份或 WikiLink。
- 规律需要至少两个不同月份，或两类独立素材支持。只有单次事件时写成观察，不上升为季度规律。
- 工作、学习、健康、家庭与关系按“是否出现重要变化”筛选；没有变化或没有可靠证据的维度不为凑结构而扩写。
- 比较上季度时只使用现成且口径可比的数据。缺少可靠基线就省略环比，只写当前季度事实。
- 引用原文要短，优先概括。素材冲突时说明冲突，并采用时间更近、来源更直接或证据更完整的一项。

## 回顾流程

1. 确定目标季度、三个月份、上一季度及日期边界。
2. 枚举目标季度的月回顾和相交周回顾，记录缺失月份与覆盖范围；仅针对缺口和关键争议下钻日记或晨记。
3. 建立去重后的事实清单：季度初目标、关键结果、未完成事项、学习产出、健康与家庭变化。
4. 从上一季度回顾的“下季度重点”、目标季度第一个月回顾或季度初记录中恢复季度目标。找不到时写“未找到明确季度目标”，不要事后虚构。
5. 提炼季度主题和 3～5 项关键结果；删除只说明过程、没有结果或影响的普通事项。
6. 识别最多 3 条跨月规律或教训，并为每条保留简短证据线索。
7. 给出下季度 3 个优先事项，每项包含可验证结果；再用一句话概括停止、继续、开始。
8. 读取本 Skill 目录下的 `references/quarterly-review-template.md`，按其篇幅预算生成正文。目标是 3～5 分钟读完；宁可少写，也不要把三份月回顾拼接成长文。
9. 将结果写入 `journals-month/YYYY-Qn.md`：
   - 文件不存在时创建。
   - 用 `<!-- quarter-review:YYYY-Qn:start -->` 和 `<!-- quarter-review:YYYY-Qn:end -->` 包围生成内容，作为稳定的幂等标记。
   - 文件存在但没有对应季度标记时，先检查旧版无标记回顾。只有能唯一识别同一季度标题和完整主体时，才将它原位升级为带标记区块；边界不明时停止并报告。没有可迁移旧区块时才在末尾追加，保留原文。
   - 已存在完整标记时，默认停止并说明该季度回顾已经生成；只有用户明确要求重新生成或更新时，才替换标记之间的内容。
   - 只有单侧标记时视为结构损坏，停止写入并报告。
   - 追加到非空文件前插入空行和 `---`，让新旧内容边界清楚。
10. 写入后重新读取生成区块，确认开始和结束标记各出现一次，并检查标题、时间范围、素材覆盖、所有模板章节和落盘路径。

## 输出要求

成功写入并验证后，聊天中只回复：`创建完成`

若无法确定季度、找不到 vault、没有任何目标季度素材、目标区块已存在且用户未要求更新、标记损坏或写入失败，不要回复“创建完成”；简洁说明阻塞原因和需要用户处理的事项。

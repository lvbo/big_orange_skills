# 增量同步当日计划

把当前 Apple Calendar 和 Things Today 中尚未写入的项目补充到 `journals/YYYY-MM-DD.md`。这是一项保守的增量合并：日记里已有的内容代表用户已经整理过的工作现场，不要重建“每日计划”，也不要用外部数据覆盖用户手工编辑。

## 数据范围

### Apple Calendar

- 查询“工作”“个人”“吕波”三个日历。
- 使用本机时区当天的半开区间 `[今日 00:00, 明日 00:00)`。
- 通过 `date` 计算日期边界，不凭会话中的日期猜测。
- 所有 `accli calendars` 和 `accli events` 命令直接在非沙箱环境运行。用户已授权这些命令，无需再次确认。
- 如果非沙箱执行仍返回 `NOT_AUTHORIZED`，报告 macOS 日历权限问题；不要把沙箱权限错误解释成用户未授权。
- 优先使用 JSON，便于准确读取 `summary`、`location`、`allDay`、`start` 和 `end`。

示意命令：

```bash
accli events 工作 --from YYYY-MM-DD --to YYYY-MM-DD --json
accli events 个人 --from YYYY-MM-DD --to YYYY-MM-DD --json
accli events 吕波 --from YYYY-MM-DD --to YYYY-MM-DD --json
```

### Things

- 运行 `things today --format json --select uuid,title,status,today_index`。
- 保持 Things Today 返回的顺序。
- 使用默认状态过滤，只同步当前 Today 中未完成的待办；不要使用 `--status any` 或 `--all`。
- 只把 `title` 写入日记，不写 UUID、项目、区域、标签或其他元数据。
- 此流程只读取 Things，不修改 Things 数据。

## 写入目标

1. 通过本机 `date +%Y-%m-%d` 得到今天。
2. 目标文件是 Vault 中的 `journals/YYYY-MM-DD.md`。
3. 先读取完整文件，再定位 `### 每日计划`。
4. 如果当日日记或 `### 每日计划` 不存在，停止并说明缺少的目标；不要擅自用模板创建或重建日记。本 Skill 只做增量同步。

## 格式化规则

### 日历

定时日程写在“会议”节点下，缩进一个 Tab：

```markdown
- 会议
	- [HH:mm～HH:mm] 日程名称 日程地点 [时间花费]
```

- 地点为空时省略地点及其前置空格。
- 时间花费使用便于阅读的中文：`30分钟`、`1小时`、`1小时30分钟`。
- 全天日程使用 `[全天] 日程名称 日程地点`，不虚构起止时间和时长。
- 按开始时间排序；同一时间按日历查询顺序“工作”“个人”“吕波”稳定排序。

### Things

Things 待办写成“每日计划”的直接子项，放在完整“会议”节点之后：

```markdown
- 待办标题
```

不要自动添加 `TODO`、复选框、UUID、来源标签或番茄标记。

## 增量合并

### 保护边界

- 不删除任何日记内容。
- 不重排、不改写已有条目。
- 不改变 `DONE`、复选框、缩进、番茄/土豆标记、块 ID、链接、批注或用户追加的工时。
- 不修改 `### 每日计划` 之外的任何区域，尤其是“Habit Tracker”和“每日投入”。
- 新内容只能插入到 `### 每日计划` 的范围内；该范围结束于下一个同级或更高级 Markdown 标题，或文件末尾。

### 判重

判重时只决定“是否新增”，绝不借机规范化原有文本。

日历条目视为已存在的条件：

- 在“会议”节点的现有子项中，能找到相同的开始时间、结束时间和日程名称。
- 比较前忽略项目符号、缩进和状态前缀（如 `DONE`、`TODO`、`[ ]`、`[x]`）。
- 允许原有条目在末尾带地点、时长、工时、标签或其他用户批注。

Things 条目视为已存在的条件：

- “每日计划”内存在标题相同的直接子项。
- 比较前忽略项目符号、状态前缀、首尾空白、块 ID，以及用户在标题之后追加的状态或投入标记。
- 只有可以可靠确认是同一待办时才跳过；不要使用模糊关键词匹配，以免漏掉真正的新任务。

如果日历事件发生改期或改名，旧日记内容仍需保留；把当前版本作为新条目补充进去，并在结果中提示“检测到疑似改期/改名，已按保守策略新增，未删除旧条目”。

### 插入位置

1. 找到“每日计划”下的 `- 会议` 节点。
2. 如果存在，向该节点末尾追加缺失日程。
3. 如果不存在，在“每日计划”开头创建 `- 会议`，再写入缺失日程。
4. 把缺失 Things 待办插入完整“会议”节点之后、其他已有直接子项之前。
5. 若没有任何新增项，不修改文件。

## 执行与验证

1. 读取三类日历、Things Today 和目标日记。
2. 在内存中计算缺失日程与缺失待办。
3. 修改前再次确认编辑范围只落在 `### 每日计划` 内。
4. 使用精确补丁编辑文件，不整篇覆写。
5. 重新读取目标文件并验证：
   - 每个新增项恰好出现一次；
   - 所有原有文本仍然存在；
   - 日历项位于“会议”下；
   - Things 项位于“每日计划”的直接子项；
   - “每日计划”之外没有变化。

## 报告格式

简洁报告：

```text
已同步 journals/YYYY-MM-DD.md
- 新增日历：N 项
- 新增 Things：N 项
- 已跳过重复：N 项
```

分别列出实际新增的标题。如果没有新增，明确说明“当前日历和 Things Today 均已同步，日记未修改”。遇到疑似改期/改名、权限错误或缺失日记结构时，单独说明，不要声称同步完整成功。
